# 新建自定义策略

按以下流程引导用户创建/修改自定义策略，严格以项目真实策略体系为准（见 `docs/strategy.md` 与 `backend/app/strategy/prompts/` 下的策略开发规范，机制以 `backend/app/strategy/engine.py` 与 `backend/app/main.py` 中 StrategyEngine 的 `strategy_dirs` 为准），不虚构不存在的 API 或流程。

执行步骤：
1. 收集策略意图：名称、选股逻辑、入池/排序/过滤条件、参数与默认值、目标资产类型（股票/ETF）与运行周期（日线/分钟）、所需历史窗口。
2. 先判断能否用现有内置策略参数、自定义信号或叠加（composite）方式表达；若可以则引导用该方式（不新建平行机制），并说明选择理由。
3. 确认落盘与形态：用户策略文件属于用户数据（默认 `data/strategies/` 对应子目录），ID 唯一稳定，新建不覆盖既有策略。**先展示拟写入的文件结构与关键代码片段，获得确认后再写入。**
4. 以 `backend/app/strategy/builtin/` 中 1-2 个最接近的真实内置策略为参考实现参数/过滤/评分/结果契约；沿用 enriched 现算指标与信号列，不自行造列。
5. 口径核对：复权/换手/涨跌幅、交易日与北京时间、股票/ETF/指数不串、评分缺输入返回"不可计算"。
6. 接线与缓存：核对策略结果缓存、监控实例与前端查询是否需要同步刷新。
7. 验证：执行 `run-verification` 技能或 `CONTRIBUTING.md` §9 矩阵中策略类最低验证（后端对应测试 + 边界/失败路径；如涉及前端字段则 `pnpm build`），如实汇报命令与结果。
8. 输出总结：方案归类（应为 L1）、落盘路径、策略契约、验证结果、剩余风险；不自动 commit/push。
